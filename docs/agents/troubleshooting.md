# Troubleshooting Documentation Rules

트러블슈팅은 실제로 발생한 문제를 재현하고 원인을 분석해 해결한 과정을 기록하는 문서다.

## 적용 대상

- 재현 가능한 버그·오류의 해결 과정
- YouTube URL 파싱, 외부 API 응답, SVG 렌더링, 데이터 저장, 배포·빌드 문제의 분석
- 처음 세운 가설과 실제 원인이 달랐던 디버깅 경험
- 재발 방지 가치가 있는 원인 분석

기술 선택·라이브러리 도입·구조 개선은 `tech-note.md`, GitHub 작업은 `github.md`, PR 리뷰는 `pr-review.md`를 사용한다.

## 기본 구성

1. 문제 상황
2. 재현 조건
3. 처음 세운 가설
4. 디버깅 과정
5. 실제 원인
6. 해결 방법
7. 검증 결과
8. 재발 방지와 남은 한계
9. 관련 코드와 PR

## 작성 원칙

- 해결 방법만 나열하지 않고 발생 원인과 확인 근거를 설명한다.
- 가설과 실제 원인을 구분한다.
- 실제로 확인하지 않은 원인·성능 수치·재발 방지 효과를 단정하지 않는다.
- Before / After, 로그, 재현 절차는 이해에 필요한 범위만 포함한다.
- 문서는 한국어로, 짧고 사실적인 문단 위주로 작성한다.

## Notion 저장

- 사용자가 지정한 Notion 데이터베이스 또는 페이지에만 저장한다.
- 저장 전에는 전체 초안을 먼저 보여주고 명시적 승인을 받는다.
- 저장 전 대상 스키마와 유사 문서를 확인한다.
- 저장 후 제목·속성·본문을 다시 조회해 정상 등록을 확인한다.
