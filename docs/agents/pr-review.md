# PR Review Agent Rules

PR 리뷰는 실제 diff와 현재 코드에 근거해, 반드시 수정할 문제와 선택적 개선을 구분하는 작업이다. GitHub에 게시하기 전에는 리뷰 코멘트 후보를 먼저 보여준다.

## 확인 순서

1. PR 제목, 본문, 브랜치, 변경 파일, diff를 확인한다.
2. 기존 리뷰 코멘트와 unresolved thread를 확인해 중복을 피한다.
3. 서비스 동작, 데이터·보안, 예외 처리, 테스트, 접근성, 성능 순으로 검토한다.
4. 발견 사항은 가능한 한 diff 안의 구체적인 위치에 연결한다.

## Pn 룰

- **P1**: 보안, 데이터 손상, 서비스 장애, 주요 기능 실패 가능성. 반드시 수정이 필요하다.
- **P2**: 실제 버그 가능성 또는 높은 유지보수 위험. 수정을 강하게 권장한다.
- **P3**: 품질·테스트·명확성 개선. 특별한 이유가 없으면 반영을 권장한다.

개인 취향이나 사소한 제안은 초기 단계에서는 인라인 리뷰 코멘트로 남기지 않는다.

## 코멘트 기준

- 현재 diff와 코드로 확인 가능한 내용만 단정한다.
- 근거가 부족하면 확인 질문으로 작성한다.
- 작성자의 의도를 추정하지 않는다.
- diff 밖 기존 코드에는 인라인 코멘트를 남기지 않는다.
- 발견 사항이 없으면 억지로 작성하지 않고, 실행하지 못한 검증의 한계만 밝힌다.

## 출력 형식

```md
## PR 리뷰 코멘트 후보

### 1. `파일 경로:라인`

- 등급: P2
- 이유: 문제 원인과 사용자 또는 유지보수 영향
- 제안 코멘트:

> [P2] 문제를 한 문장으로 설명합니다.
>
> 현재 ... 때문에 ... 문제가 발생할 수 있습니다.
> ... 방향으로 처리하는 것을 고려해 주세요.
```
