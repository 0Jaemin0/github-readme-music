# Tech Note Documentation Rules

Tech Note는 기술·구조 선택의 이유와 트레이드오프를 남기는 문서다. 구현 결과 나열보다 선택 기준과 근거를 중심으로 작성한다.

## 적용 대상

- 프레임워크, 라이브러리, 호스팅, 데이터베이스, 외부 API 도입·교체
- 카드 SVG 생성·캐싱·공개 URL 정책
- `Song`, `YouTube Video`, `Card` 데이터 모델과 식별자 정책
- 컴포넌트·상태 관리·공통 모듈 구조 개선
- 성능, 접근성, 사용자 경험을 위해 검토한 기술적 대안

명확한 버그의 재현·원인·해결은 `troubleshooting.md`에 별도로 기록한다.

## 기본 구성

1. 제목과 요약
2. 배경과 제약
3. 기존 방식 또는 해결할 문제
4. 검토한 대안
5. 선택한 방법과 이유
6. 구현 구조 또는 적용 범위
7. 검증 결과
8. 트레이드오프와 남은 한계
9. 관련 코드, PR, 참고 자료

## 작성 원칙

- 실제 코드, 요구사항, 검증 결과를 확인한 뒤 작성한다.
- 사실·가정·추론을 구분한다.
- 선택하지 않은 대안과 그 이유를 짧게 남긴다.
- 측정하지 않았으면 성능 개선을 단정하지 않는다.
- 특정 기술이 모든 상황에서 더 낫다고 일반화하지 않는다.
- 현재 프로젝트 요구사항에서의 적합성과 추가 책임을 설명한다.
- 문서는 한국어로 작성하고, 독자가 맥락을 이해하는 데 필요한 배경만 제공한다.

## Notion 저장

- 사용자가 지정한 Tech Note 또는 문서 데이터베이스에만 저장한다.
- 대상이 없으면 임의로 새 데이터베이스를 만들지 않는다.
- 저장 전 전체 초안, 대상 스키마, 유사 문서를 확인한다.
- 저장 후 제목·속성·본문을 다시 조회하고 링크를 전달한다.
