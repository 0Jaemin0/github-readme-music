# Technical Documentation

문서 목적에 따라 정책을 선택한다.

- 재현, 원인 분석, 해결 과정이 핵심이면 `docs/agents/troubleshooting.md`를 읽는다.
- 기술 선택, 구조 개선, 라이브러리·인프라 도입 판단이 핵심이면 `docs/agents/tech-note.md`를 읽는다.
- 두 성격이 모두 있으면 문서를 분리하고 서로 연결한다.

1. 관련 코드, 변경 내역, 테스트·디버깅 결과를 확인한다.
2. 사실·가정·검증 결과를 구분해 초안을 작성한다.
3. 전체 초안을 사용자에게 먼저 보여준다.
4. 사용자가 명시적으로 승인한 경우에만 지정된 Notion 데이터베이스 또는 페이지에 저장한다.
5. 저장 전 대상 스키마와 유사 문서를 확인하고, 저장 후 생성 결과를 다시 조회해 검증한다.

실제로 확인하지 않은 원인이나 성능 개선은 사실처럼 작성하지 않는다.
