# PR Review

먼저 `docs/agents/pr-review.md`를 읽고 판단 기준과 출력 형식을 적용한다.

1. 대상 PR의 제목, 본문, 브랜치, 변경 파일, diff를 확인한다.
2. 기존 리뷰와 unresolved thread를 확인한다.
3. 서비스 동작, 데이터·보안, 예외 처리, 테스트, 접근성, 성능 순으로 검토한다.
4. 발견 사항마다 diff 안의 구체적인 위치, Pn 등급, 원인, 영향, 제안 방향을 포함한 한국어 후보를 작성한다.
5. GitHub에 게시하기 전에는 후보만 보여주고, 명시적 승인 후에만 코멘트를 남긴다.

근거가 부족한 내용은 단정하지 않고 확인 질문으로 남긴다.
