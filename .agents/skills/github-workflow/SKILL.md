# GitHub Workflow

먼저 `docs/agents/github.md`와 현재 `.github` 템플릿을 확인한다.

1. 저장소 상태, 현재 브랜치, remote를 확인해 작업 범위와 기존 사용자 변경사항을 구분한다.
2. 요청에 맞는 이슈·PR 템플릿과 관련 이슈 또는 PR 정보를 확인하고, 현재 사용 가능한 라벨을 확인한다.
3. 이슈·PR 초안에는 제목·본문뿐 아니라 Assignee와 최소 하나의 작업 성격 라벨을 포함한다. 제목에는 `feat:`, `fix:`, `chore:`, `docs:` 같은 작업 성격 접두어를 붙이지 않고 작업 내용만 작성한다.
4. 이슈, PR, 리뷰 코멘트의 생성·수정 요청이면 전체 초안을 먼저 제시하고 명시적 승인을 기다린다.
5. 승인된 범위에서만 GitHub 변경, 브랜치 생성, 커밋을 수행한다.
6. 스택에 정의된 검증을 실행하고, 결과와 실행하지 못한 검증의 이유를 정리한다.

기존 사용자 변경사항, 작업 범위 밖 파일, 불명확한 제품·서버 정책은 임의로 확정하지 않는다.
GitHub Issue Form의 선택 입력은 내용이 없으면 비워 두고, PR Markdown 템플릿의 선택 섹션은 제목과 안내문까지 제거한다.
