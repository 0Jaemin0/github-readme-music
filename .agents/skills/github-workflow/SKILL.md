# GitHub Workflow

먼저 `docs/agents/github.md`와 현재 `.github` 템플릿을 확인한다.

1. 저장소 상태, 현재 브랜치, remote를 확인해 작업 범위와 기존 사용자 변경사항을 구분한다.
2. 요청에 맞는 이슈·PR 템플릿과 관련 이슈 또는 PR 정보를 확인한다.
3. 이슈, PR, 리뷰 코멘트의 생성·수정 요청이면 전체 초안을 먼저 제시하고 명시적 승인을 기다린다.
4. 승인된 범위에서만 GitHub 변경, 브랜치 생성, 커밋을 수행한다.
5. 스택에 정의된 검증을 실행하고, 결과와 실행하지 못한 검증의 이유를 정리한다.

기존 사용자 변경사항, 작업 범위 밖 파일, 불명확한 제품·서버 정책은 임의로 확정하지 않는다.
